# editor サーバーを複数プロセスで動かす (nginx で 1 つのポートにまとめる)

クラウドソーシングなどで同時に何人もが合成を頼むとき用の手順です。
`server_editor.py` を複数起動し、その前にユーザー権限の nginx を置いて、1 つのポートで受けます。
クライアント (pooh_body の TTS ノードやチャットボットの web UI) は、これまでと同じ URL (`http://127.0.0.1:8000`) に送るだけです。

使うファイルは [`docs/multi_server/`](multi_server/) にあります。

| ファイル | 役割 |
|---|---|
| `run_servers.sh` | nginx と `server_editor.py` を tmux セッション `sbv2` の中で起動する |
| `nginx.conf.in` | nginx の設定のひな形 (`run_servers.sh` がポートなどを埋めて使う) |

## 必要なもの

- このリポジトリの `venv/` (PyTorch が CUDA で動くもの) とモデル (`model_assets/new_model3/` など)
- `nginx` と `tmux` (`sudo apt install nginx tmux`)。
  システムの nginx (80 番) の設定には触らず、別の nginx をユーザー権限で動かすので、起動に sudo は要りません

## 起動

```bash
cd ~/Style-Bert-VITS2
docs/multi_server/run_servers.sh 2 8000
```

- 引数は `[プロセス数] [ポート]` です。nginx がポートで受け、ポート+1 から プロセス数 個の `server_editor.py` に振り分けます。
  上の例では nginx が 8000、サーバーが 8001 と 8002 です。
- 起動後、各サーバーにモデルを 1 回合成させて読み込ませておきます (約 20 秒)。
  `ready: http://127.0.0.1:8000 -> 2 processes on 8001-8002` と出たら使えます。
- 読み込むモデルは環境変数 `MODEL` (既定 `new_model3`)、デバイスは `DEVICE` (既定 `cuda`) で変えられます。
- tmux の中で動くので、起動したターミナルや Claude Code のセッションを閉じても止まりません。
  PC を再起動したら、もう一度起動してください (常駐はさせていません)。
- すでにセッション `sbv2` があると起動しません。先に止めてください。

## 様子を見る・止める・戻す

```bash
tmux attach -t sbv2                       # 各プロセスのログを見る (Ctrl-b n で次の窓、Ctrl-b d で抜ける)
tmux kill-session -t sbv2                 # すべて止める (nginx も一緒に止まる)
tmux respawn-window -k -t sbv2:tts8002    # 落ちたプロセスだけを起動し直す
```

nginx のログと設定は `$XDG_RUNTIME_DIR/sbv2-nginx/` (`/run/user/<uid>/sbv2-nginx/`) にあります。

## 振る舞い

- 振り分けは `least_conn` (処理中のリクエストが少ないプロセスへ送る) です。
- 1 つのプロセスが落ちても、nginx はそのプロセスに送った POST を残りのプロセスで送り直すので、クライアントにはエラーが返りません。
  落ちたプロセスは上の `respawn-window` で戻します。
- 文章を読みに変える pyopenjtalk の worker は、最初に起動したプロセスが立ち上げ、全プロセスで共有します。
  そのため、ユーザー辞書 (`/api/user_dict_word`) はどのプロセスに登録しても全体に効きます。
- 1 つのプロセスが持てるモデルは 1 つだけです。起動時に読み込ませたものと違うモデルを送ると、そのたびに読み直し (約 0.5 秒) が入ります。
- `new_model3` は pitch・抑揚 1.0 で使います。1.0 以外にすると、CPU での f0 の作り直しが入って 1 文に 0.9 秒ほどかかります。

## 実測 (RTX 3090 Ti、new_model3、pitch・抑揚 1.0)

1 文の g2p + 合成にかかった時間の中央値です。

| 同時リクエスト数 | 1 プロセス | 2 プロセス + nginx |
|---|---|---|
| 1 | 0.17 秒 | 0.18 秒 |
| 5 | 0.56 秒 | 0.34 秒 |
| 10 | 1.20 秒 | 0.62 秒 |
| 25 | 3.35 秒 | 1.63 秒 |

1 プロセスはおよそ 1 秒に 6 件を処理します。プロセス 1 つあたりの使用量は、アイドル時で GPU メモリ約 2〜3 GB と RAM 約 2 GB です。
同時アクセスが多いと最大で GPU メモリ約 7 GB、RAM 約 10 GB まで増えます。
50 人が 30 分の間にばらばらに参加する程度なら、同時に合成が走るのは数件なので、2 プロセスで十分です
(2 つにしているのは、片方が落ちても止まらないようにするためです)。
